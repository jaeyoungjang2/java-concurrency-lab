E03_Executor
- 쓰레드풀 활용 가능 -> 스레드 생성에 필요한 오버헤드 감소 및 자원 사용량 최적

이제 쓰레드 풀을 미리 생성해놓고 작업을 할 수 있게 되었다.
오늘날 대부분의 웹 서비스는 요청 당 1개의 쓰레드를 할당한다.
요청이 들어오면 서블릿 컨테이너는 요청을 스레드 풀에 있는 하나의 스레드 풀에 할당한다.
쓰레드 풀을 많이 생성할 수록 속도가 빨라질까?
- 최대 쓰레드 수의 제한: 자바 쓰레드는 네이티브 스레드를 얇게 감싼 쓰레드, 즉 생성 가능한 최대 개수는 운영체제의 네이티브 스레드 최대 개수에 의해 제한된다.
- 메모리 사용량: 스레드가 힙 외부에서도 약 2Mib에 달하는 공간을 사용, 수천개의 동시 요청이 발생하면 메모리 사용량이 급증할 수 있다.
- 컨텍스트 전환 비용: 쓰레드 사이의 전환 즉 컨텍스트 전환 비용은 CPU 사이클을 소모하고, 이런 부분에서 성능 차이가 발생할 수 있다.
